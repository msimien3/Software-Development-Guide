Dapper with MSSQL & Oracle

One model. Two database providers. No DbContext required.

01 NuGet02 Model03 Program04 Run05 Parameters06 Troubleshooting

01Install the NuGet packages

Open or create a modern .NET Console App in Visual Studio. In Solution Explorer, right-click the project and select Manage NuGet Packages. Select Browse, search for each package below, and click Install. Use versions compatible with your project's target framework.

PackagePurpose
DapperMaps SQL results to C# objects.
Microsoft.Data.SqlClientMicrosoft SQL Server connection provider.
Oracle.ManagedDataAccess.CoreOracle connection provider for modern .NET.
C# application→Dapper→SQL Server / Oracle provider→Database

No Entity Framework, custom ORM, DbContext or dependency injection is required.

02Create your model

Right-click your project → Add → Class. Name it Coil.cs. Dapper matches returned column names to the properties in this class.

public class Coil
{
    public int Id { get; set; }
    public string CoilNumber { get; set; } = "";
    public double Weight { get; set; }
}

The sample assumes the query returns Id, CoilNumber and Weight with compatible types in both databases. Verify your actual schema; alias columns if needed and use nullable properties for nullable values.

Project structure

MillApplication/
    Program.cs   // Queries and console output
    Coil.cs      // Shared data model

03Query both databases

Replace the contents of Program.cs with the code below. Supply your approved SQL Server and Oracle connection strings through environment variables.

Local training only: Credentials are intentionally omitted. Configure connection strings using environment variables. For production, load connection strings from approved secret storage or secure configuration. Consider rotating credentials that have been exposed.
using System;
using System.Collections.Generic;
using System.Linq;
using Dapper;
using Microsoft.Data.SqlClient;
using Oracle.ManagedDataAccess.Client;

string sqlConnectionString =
    Environment.GetEnvironmentVariable("MSSQL_CONNECTION_STRING") ?? throw new InvalidOperationException("Set MSSQL_CONNECTION_STRING");

string oracleConnectionString =
    Environment.GetEnvironmentVariable("ORACLE_CONNECTION_STRING") ?? throw new InvalidOperationException("Set ORACLE_CONNECTION_STRING");

string query = "SELECT * FROM Coils WHERE Weight > 20";

// Microsoft SQL Server
using var sqlConn = new SqlConnection(sqlConnectionString);
List<Coil> sqlCoils = (await sqlConn.QueryAsync<Coil>(query)).ToList();

Console.WriteLine("MSSQL coils:");
foreach (Coil coil in sqlCoils)
{
    Console.WriteLine($"{coil.CoilNumber}: {coil.Weight} tons");
}

// Oracle
using var oracleConn = new OracleConnection(oracleConnectionString);
List<Coil> oracleCoils = (await oracleConn.QueryAsync<Coil>(query)).ToList();

Console.WriteLine("Oracle coils:");
foreach (Coil coil in oracleCoils)
{
    Console.WriteLine($"{coil.CoilNumber}: {coil.Weight} tons");
}

What each part does

SqlConnectionConnects to MSSQL.
OracleConnectionConnects to Oracle.
QueryAsync<Coil>()Executes the query asynchronously and maps rows to Coil objects.
awaitWaits for query completion without blocking during asynchronous I/O.
ToList()Converts results into a List<Coil>.
using varDisposes the connection at the end of the scope; Dapper opens a closed connection for the query automatically.

04Run and display the results

Press Ctrl+F5 in Visual Studio. Example output (illustrative, not retrieved from your servers):

MSSQL coils:
C1001: 23.5 tons
C1003: 25.2 tons

Oracle coils:
C2001: 22.7 tons

The queries run sequentially. If the first query fails, execution stops before the second. You must have network access and SELECT permissions on both databases.

05Use parameterized queries

For a variable filter, use parameters rather than concatenating user input into SQL. Add this code before the end of Program.cs, where the connection variables are still in scope.

double minWeight = 20;

List<Coil> sqlResults = (await sqlConn.QueryAsync<Coil>(
    "SELECT * FROM Coils WHERE Weight > @MinWeight",
    new { MinWeight = minWeight }
)).ToList();

List<Coil> oracleResults = (await oracleConn.QueryAsync<Coil>(
    "SELECT * FROM Coils WHERE Weight > :MinWeight",
    new { MinWeight = minWeight }
)).ToList();

SQL Server uses @MinWeight; Oracle uses :MinWeight. This single-parameter Oracle example avoids positional binding ambiguity.

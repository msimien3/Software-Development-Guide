Entity Framework Core with MSSQL & Oracle

One model. Two DbContexts. Raw SQL and LINQ.

01 NuGet02 Model03 DbContext04 Program05 Run06 Parameters07 Troubleshooting

01Install the NuGet packages

Create or open a modern .NET Console App in Visual Studio. Right-click the project in Solution Explorer → Manage NuGet Packages → Browse. Search for each package, select the project and click Install.

PackagePurpose
Microsoft.EntityFrameworkCore.SqlServerEF Core provider for Microsoft SQL Server.
Oracle.EntityFrameworkCoreEF Core provider for Oracle.

Both providers bring in the required EF Core dependencies. Choose compatible provider versions for the same EF Core major version and your target .NET framework. Check the Oracle package's Dependencies tab before installing. No CLI, migration tools or Dapper required.

Oracle compatibility: Verify your Oracle server version before choosing the provider. Modern Oracle EF Core versions have SQL compatibility options for newer Oracle releases (19, 21, 23); older servers may require older providers or a different data-access approach.
C# application→DbContext / EF Core→SQL Server or Oracle provider→Database

02Create the Coil model

Right-click your project → Add → Class. Name it Coil.cs. This class represents a row from the Coils table.

public class Coil
{
    public int Id { get; set; }
    public string CoilNumber { get; set; } = "";
    public double Weight { get; set; }
}

Id is recognized as a primary key by EF Core convention. This example assumes the table has a corresponding unique key and compatible column types. Adjust mappings and nullability to your real schema. For a read-only source without a key, configure a keyless entity with HasNoKey() instead.

Project structure

MillApplication/
    Program.cs        // Connections, queries and output
    Coil.cs           // Shared entity model
    SqlMillContext.cs  // MSSQL configuration
    OracleMillContext.cs // Oracle configuration

03Create both DbContext classes

Unlike Dapper, EF Core requires a context to manage the database provider and entity mapping. DbSet<Coil> exposes the mapped Coils table. Separate contexts make each database's table and column mappings explicit.

SqlMillContext.cs

using Microsoft.EntityFrameworkCore;

public class SqlMillContext : DbContext
{
    private readonly string _connectionString;

    public SqlMillContext(string connectionString)
    {
        _connectionString = connectionString;
    }

    public DbSet<Coil> Coils => Set<Coil>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseSqlServer(_connectionString);
    }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Coil>().ToTable("Coils");
    }
}

OracleMillContext.cs

using Microsoft.EntityFrameworkCore;

public class OracleMillContext : DbContext
{
    private readonly string _connectionString;

    public OracleMillContext(string connectionString)
    {
        _connectionString = connectionString;
    }

    public DbSet<Coil> Coils => Set<Coil>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseOracle(_connectionString);
    }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Coil>(entity =>
        {
            entity.ToTable("COILS");
            entity.Property(c => c.Id).HasColumnName("ID");
            entity.Property(c => c.CoilNumber).HasColumnName("COILNUMBER");
            entity.Property(c => c.Weight).HasColumnName("WEIGHT");
        });
    }
}

Oracle normally stores unquoted identifiers in uppercase. If the real table is owned by another schema, use ToTable("COILS", "OWNER") and qualify the raw SQL too. Change these mappings if your actual identifiers differ.

04Program.cs — complete example

Replace the contents of Program.cs with this example. It demonstrates four independent queries: MSSQL raw SQL, MSSQL LINQ, Oracle raw SQL and Oracle LINQ. Each produces a List<Coil> and prints the results.

Private training file: Connection strings are supplied through environment variables. Never commit actual credentials to GitHub. In production, use environment variables or an approved secret store.
using Microsoft.EntityFrameworkCore;

string sqlConnectionString =
    Environment.GetEnvironmentVariable("MSSQL_CONNECTION_STRING") ?? throw new InvalidOperationException("Set MSSQL_CONNECTION_STRING");

string oracleConnectionString =
    Environment.GetEnvironmentVariable("ORACLE_CONNECTION_STRING") ?? throw new InvalidOperationException("Set ORACLE_CONNECTION_STRING");

// MSSQL
using var sqlDb = new SqlMillContext(sqlConnectionString);

List<Coil> sqlRawCoils = await sqlDb.Coils
    .FromSqlRaw("SELECT * FROM Coils WHERE Weight > 20")
    .AsNoTracking()
    .ToListAsync();

List<Coil> sqlLinqCoils = await sqlDb.Coils
    .Where(c => c.Weight > 20)
    .AsNoTracking()
    .ToListAsync();

// Oracle
using var oracleDb = new OracleMillContext(oracleConnectionString);

List<Coil> oracleRawCoils = await oracleDb.Coils
    .FromSqlRaw("SELECT * FROM Coils WHERE Weight > 20")
    .AsNoTracking()
    .ToListAsync();

List<Coil> oracleLinqCoils = await oracleDb.Coils
    .Where(c => c.Weight > 20)
    .AsNoTracking()
    .ToListAsync();

DisplayCoils("MSSQL - Raw SQL", sqlRawCoils);
DisplayCoils("MSSQL - LINQ", sqlLinqCoils);
DisplayCoils("Oracle - Raw SQL", oracleRawCoils);
DisplayCoils("Oracle - LINQ", oracleLinqCoils);

static void DisplayCoils(string title, List<Coil> coils)
{
    Console.WriteLine($"\n{title} ({coils.Count} coils)");

    foreach (Coil coil in coils)
    {
        Console.WriteLine($"{coil.CoilNumber}: {coil.Weight} tons");
    }
}

Run one query at a time if you're testing connections individually. The queries are sequential here; never run multiple operations concurrently on the same DbContext.

06Use parameters for dynamic values

When the weight threshold is a variable, use interpolated SQL through FromSqlInterpolated(), or LINQ. EF Core parameterizes these examples automatically.

Raw SQL — works with either context

double minimumWeight = 20;

List<Coil> coils = await sqlDb.Coils
    .FromSqlInterpolated($"SELECT * FROM Coils WHERE Weight > {minimumWeight}")
    .AsNoTracking()
    .ToListAsync();

LINQ — works with either context

double minimumWeight = 20;

List<Coil> coils = await oracleDb.Coils
    .Where(c => c.Weight > minimumWeight)
    .AsNoTracking()
    .ToListAsync();

Do not concatenate user input into SQL or interpolate it inside FromSqlRaw().
